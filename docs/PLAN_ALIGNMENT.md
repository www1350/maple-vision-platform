## 2. 状态判定规则

- **已实现并验收**：有运行代码和指定版本的独立证据；只对报告覆盖的范围成立。
- **部分实现**：有实际功能，但原章的重要能力、通用性或数据仍缺失。
- **未实现**：只有设计、接口占位或原型；不能按名称存在计作完成。
- **未验收或未通过**：功能工具可能存在，但目标效果没有证据或已明确失败。

下表逐章覆盖原文；“当前实现”均以 v0.4 基线及保留的历史证据为准。后续新增接口必须更新对应行，并关联新的独立验收，不能回写旧实验结果。

## 4. 必须显式处理的架构偏差

### A. 业务运行链尚未遵守完整任务分层

原要求是 Task → Plan → Intent → Execution → Verification。实际业务链从 `VisualAgent.decide(VisualObservation)` 直接产出包含 `SimAction` 的 `AgentDecision`，`lab.py` 驱动 `Simulator.step` 后记录效果与 oracle。原 P0 的 Intent/Execution/Verification 及 WorldState 仍是独立 NoOp 基础，不能把两条链的类型名称拼起来宣称原架构已完成。

补齐时需先冻结版本化 Task/Plan/Intent、动作冲突与时间合同，再迁移任务和职业能力；保留旧证据读取与确定性重放。现有策略只读观测、控制只接动作的边界应继续保持，不能为实现 Planner 读取动态 Ground Truth。

### B. 数据底座与资产索引采取了精简存储

通用 catalog 可保存版本化 payload，但不等同原章的 skills/skill_levels/monster_drops/map_connections/quest_requirements 等领域表及关系校验。当前三职业参数映射只消费明确核实的合成范围；不能把尚未映射的真实参考条目直接转为运行规则。素材索引目前也存为文件，尚未实现原计划的 SQLite 索引。

后续应选择显式迁移或经审查的等价领域 schema，定义实体引用、技能等级、版本一致性和冲突处理，再接运行规则。该选择属于架构决策，不能静默删减原章要求。

### C. 模拟器与产品界面的实现形态不同

现有 Python 模拟逻辑和 Pillow 渲染可无窗口运行；OpenCV 用于可选录像导入等能力。Tesseract 符合原方案“或其他本地 OCR”的选项，但中文游戏小字仍未验收。Pygame CE、FastAPI、Web UI、MapStudio 等尚未开发。

固定画布几何与静态 sprite 是当前内容子集，不代表完整镜头/动画/技能特效系统。产品层应复用确定性内核，而不是为了原型截图重新写一套规则。

### D. 七类通用检测不等于完整模型比较

当前类别为 player、monster、loot、portal、npc、platform、ladder。没有细分全部怪物身份，也没有完成 Detector + Classifier 分离或 Nano/Small/Medium 的统一对照。现有单 IoU AP 与几何指标不能替代原章全部 mAP50-95、遮挡、小目标和跨地图指标。

实验中可先导出 ONNX 以评估实际运行模型；这种导出不是原章所要求的模型准入或 Registry 发布。v0.2 的混合模型只在其合成范围通过；v0.3 单候选平台召回 472/576，低于 98% 门槛，已明确失败。其 test 和推广分支按原协议关闭，不重训或修改门槛掩盖失败。下一研究须另立候选、数据、评价及停止合同。

### E. 状态、职业、地图和回复都尚非通用实现

`VisualObservation` 和原 P0 WorldState 不能替代带字段级有效期的完整状态融合。三种固定 `ClassSpec` 可调参数也不能替代能力编译器。循环路线与静态地图标记不能替代地图图/平台图和真实 MapRecognizer。

模拟器 NPC 对话可运行；`chat_draft(incoming, reply)` 只封装调用方给定回复，既无聊天理解、自动草稿生成，也无发送后端。后续草稿能力仍须保留人工确认边界。怪物当前不自动刷新，当前清场式任务不是持续刷怪机制。

### F. 验证和发布必须沿用各自的证据范围

文件哈希证明内容一致，不能证明来源许可或官方规则正确；纯接口隔离也不是进程权限沙箱。固定录像能检验既有画面的感知，无法通过更换动作改变画面，不能验收反事实技能或药品效果。真实领域需独立录像和标注，长稳需实际墙钟。

当前证据包已有可靠重放核心，但尚未完全实现原章 Failure Bundle 各层文件与 MP4。工程测试通过、模型准入、真实域通过、24 小时通过必须分列。

## 角色键位到离线任务执行

第 10、11、15、20 章的工作台任务可选择浏览器中已确认的角色键位。支持的模拟技能在调度授权后必须解析到配置键；配置、逐步解析和实际动作同时进入自包含运行包，并由 action replay 与完整 reinfer 复核。死亡之林双图的龙骑士模拟范围攻击有成功绑定完成及缺失绑定失败两类回归。该增量没有向官方客户端发送输入；移动等非技能动作仍直接来自模拟器，真实键位、枪连击距离/时序及实战效果仍须独立录像校准。

## 单次施放多段结构

第 10、12、13 章的职业包 schema 3 增加有界 `hit_count`。一次 cast 只扣一次资源、建立一次冷却和产生一份按键意图，再对稳定选出的每个目标逐段结算；提前击杀不会重复掉落。旧 schema 1/2 继续是单段并保持原内容哈希。`spear_fighter` 是纯合成的 3 段、最多 3 目标回归样例，并通过共享 Runtime 的两图/三图任务；它只证明枪连击所需的执行结构已具备，不代表国服枪连击的倍率、范围、蓝耗和动画时序已经校准。[能力包](CLASS_PACKAGES.md) · [国服枪系校准边界](calibration/CMS_SPEAR.md)

录像测量可在一个施放窗口中登记 1–16 个严格递增的可见反馈帧，并把原帧哈希、首次反馈偏移和相邻间隔带入跨报告汇总；旧单反馈报告继续按 schema 1 读取。汇总不会把可见数字直接等同伤害段，时序校准状态固定为未完成。这样真实连续实录到位后可直接核对枪连击三段，而当前仍不生成国服技能参数。

录像施放报告还可嵌入经复核的有界键位档案、档案哈希和本次施放按键。逐份来源复验会重新解析档案；汇总拒绝混合不同键位上下文。这把“角色键位”与真实录像观察接到同一份证据中，但关联仍来自复核者声明，不把画面像素误称为键盘输入证据，也不增加官方客户端控制能力。

枪连击真实资料现在另有显式采集合同和来源复验门禁。门禁核对同一技能、等级、武器、会话、画面时间基、攻速上下文、键位、左右朝向、正反例数量、可见反馈数及收招后移动标记，并对不足项输出机器可读缺口。通过只代表资料达到人工参数审查的项目下限，射程和时序校准字段仍固定为 false；当前没有合规连续国服枪连击实录，因此不会生成或发布国服技能参数。[采集边界与命令](calibration/CMS_SPEAR.md)

合成 `spear_fighter` 现已复用角色键位链完成死亡之林双图：固定键 `S` 分别触发两次 `triple_thrust`，共生成 6 个伤害段、2 次击杀，102 步 action replay 与 103 帧 reinfer 均一致。配置、逐步 dispatch 和哈希摘要保存在 release-0.10.0 报告；该 profile 明确是自写 fixture，不宣称读取到用户真实键位。

## 合成枪系技能的双图射程验收

在死亡之林Ⅰ、Ⅱ两个演练图内，使用同一份样例角色配置，以 S 键在左右两个朝向各执行五组独立试放，共 20 组。距离按施放前的角色与目标中心计算，正值表示身前。每组从有效的模拟器存档开始，目标有 100 HP。

| 目标位置 | 每次可观察的模拟结果 | 通过组数 |
| --- | --- | --- |
| 同层身前 57、58 像素 | 各命中 3 段，目标减少 36 HP | 8/8 |
| 同层身前 59 像素或身后 1 像素 | 施放成功，目标 HP 未变 | 8/8 |
| 玩家站上层平台，目标在地面且身前 30 像素 | 施放成功，目标 HP 未变 | 4/4 |

20 次施放各耗 7 MP，紧接着的第二次按键均被冷却拒绝。固定站位用于测量单项技能；原先的 102 步双图任务继续验证走位与过图。可用 `python -m pytest -q tests/test_task_input_bindings.py -k spear_range` 复现。结论仅适用于自写的 `spear_fighter` 和上述两张演练图，国服实录校准仍待完成。

## 标飞接绳换层后的双飞斩闭环

任务程序 schema 2 可在每张地图的第一个阶段声明目标平台和必须出现的梯子边。Runtime 只从画面中的角色框建立起点，平台图给出有界固定步路径；每一步实际进入原模拟器，下一帧再用视觉坐标核对。独立任务 oracle 读取模拟真值，只在角色确实站上声明平台时记录 `navigate` 见证。旧 schema 1 任务序列和哈希保持不变。

种子 17 的标飞合成实例在死亡之林Ⅰ、Ⅱ分别用 41、83 步到达第一层平台，共执行 32 个爬绳步。每次换层确认后重新选择画面中的地面目标，离开平台并完成双飞斩；总计 4 次施放、8 段命中、2 次击杀，弹药 200→192。266 步动作回放及 267 帧完整重推理一致。错误技能档案在完成第一图换层后拒绝 12/12 次施放，零命中，145 帧重推理一致。

四类证据另有有界机器账本：复验时重算所有引用文件哈希、实录覆盖哈希及事件报告来源关系，并从两份归档重新执行正例和错误键位反例的动作重放与完整重推理。输出把真实录像、合成机制、角色键位和耗镖保持为四个独立栏位；由于原 MP4/导入帧不入仓，真实栏明确为持久报告复验而非像素重验。[复现命令与边界](THROWING_STAR_TRIAL.md)

工作台可在启动时只读登记该账本；服务端先完成同一套有界复验，浏览器才显示真实录像、合成机制、角色键位和耗镖四栏及原限制。路径只能由本机启动参数给出，页面不能替换证据输入，也不会把 `raw_pixels_reverified=false` 提升为真实像素复验。

用户提供的死亡之林Ⅰ实录已按原视频 PTS 分两个受限窗口导入全部 2197 帧。首段源帧 0–2144 保留接绳、层位变化、攻击动作和伤害反馈；尾段源帧 2145–2196 到达解码停止，并另存持续伤害反馈和攻击动作区间。独立窗口链复验强制同一 MP4 哈希、来源、尺寸和 PTS 时基，确认无缺口/重叠，覆盖哈希为 `0b2c6165e350838cce0c00263cdabb9f01efeff57aee5fc74ceea6e2c402c21f`。原视频和帧不入仓；解码停止不独立证明容器无损。报告不识别技能、施放者、目标或键盘输入，也不把时间相邻解释为因果。合成地图/机制、演示键 `S`、耗镖规则和真实实录在[标飞离线试用](THROWING_STAR_TRIAL.md)中分栏说明；不得用本轮结果宣称国服绳索坐标、双飞斩参数、耗镖或上层刷怪已经校准。

## 枪连击实录的边缘几何口径

枪连击录像汇总除人物与目标中心差外，现从已核验的起始帧标注框计算朝向归一的前向边缘间距、纵向边缘间距和纵向重叠。左右施放与不同宽度怪物因此可分栏后再用一致口径比较；可见伤害样本同时给出最远中心距离和最远非负前向边缘间距。该结果仍只是原图标注框几何，不是客户端攻击箱；MISS 与无反馈仍不生成射程上界，`calibrated_range` 继续固定为 false，直至合法连续国服实录满足独立复核门禁。

## 真实录像 Replay Viewer

第 16、20 章的工作台现可在启动时登记只读录像会话、已复验的可见事件报告和跨窗口覆盖报告。服务先完整核对 manifest、全部帧哈希、事件绑定及覆盖报告引用的来源/PTS/连续性，界面再用一条全局时间轴跨窗口显示源帧号、PTS 派生时间、当前可见事件和限制；单窗口仍可独立选择。复核者可在已验证事件的起始帧之间前后跳转，界面同时显示当前覆盖的事件和精确帧区间。浏览器请求不接受本地路径，逐帧读取会重新核对所选像素。该界面把真实资料复核与合成任务回放分开呈现，不增加客户端采集、输入或反事实动作能力，也不把标飞实录中的攻击画面认定为双飞斩。国服枪连击仍因缺少满足门禁的同技能连续实录而保持未校准。[启动与边界](WORKBENCH_NAVIGATION.md)
