# v0.2 离线平台交付验收

**当前状态：本地工程与合成混合管线模型已通过，最终发布提交的远端 CI 正在收口。** 首轮 Ubuntu 与原生训练已通过，Windows 发现旧数据精确字节哈希的跨平台差异，正在核对旧版本行为。完整架构见 [FINAL_PLAN.md](FINAL_PLAN.md)，本轮步骤见 [V0_2_PLAN.md](V0_2_PLAN.md)，机器可读合同见 [v02-contract.yaml](../engineering/v02-contract.yaml)。

## 本轮交付

- 自包含的本地知识增量计划：捕获原导出字节、来源与版本、完整目录基线；原子应用、过期拒绝、严格幂等、保留冲突及缺失历史。
- 生命周期数据集 v2：三职业、两地图、六阶段与边缘位置，通过真实动作轨迹核对画面、标注和覆盖统计；默认 v1 数据保持兼容。
- 分组检测评估：按阶段、地图、地图×阶段、玩家位置与覆盖标签重新计算指标。
- 显式 ONNX 模型进入 suite/soak；逐帧重新执行感知、监督与策略，比较 N+1 帧及终止决定。
- 有界 CPU/RSS 资源采样；保留原始失败轮次，不通过再次运行替换故障证据。
- 训练私有输入副本包含静态素材；绑定实际复制的配置和数据指纹，拒绝训练过程中输入变化。

## 模型与数据实测

数据 manifest SHA-256：`670f6dae181f0f4b3107ba6a47cb733f19cfbc216c4e8e8c23f96b756601b3ff`。训练用 480 帧；候选比较仅使用 192 帧 val；192 帧 test 保留到候选固定之后。

| 同一份 val，confidence≥0.25、IoU=0.5 | 旧模型 | 生命周期首候选 |
|---|---:|---:|
| 截断 macro AP50 | 0.900697 | 0.946252 |
| micro precision | 0.968192 | 0.998553 |
| micro recall | 0.790374 | 0.873971 |
| 平台 recall | 0.467014 | 0.661458 |
| FP / FN | 41 / 331 | 2 / 199 |

这些数字来自实际导出后的 ONNX Runtime 推理。候选依据 val 和独立合成场景固定，随后只评估一次保留 test；工程门禁在查看首候选 val 后记录，不冒称预注册实验。**test 为 192 帧、1572 个目标，TP=1372、FP=3、FN=200；micro precision=0.997818、recall=0.872774，macro AP50=0.944822。** AP 是指定置信度截断后的单 IoU 指标，不是完整 COCO mAP50–95。192 帧来自四个会话，两图都在所有 split 出现，不是未见地图或真实域准确率。

新模型在 `examples/lifecycle-model/`，ONNX SHA-256 为 `7e9f61576f63be400909db6f9eb6cb89b5b935385d01a24155c7f765d2beb6e3`；旧模型完整保留。实际推广范围为 **YOLO 动态对象＋fixture 像素地形/HUD**，动态对象没有颜色回退。运行缺省仍为像素基线，传入模型参数才用 ONNX。

纯 YOLO 地形未通过：实际 `reg_max=8`、stride 4/8 的框宽上限只有 112 像素，对全宽 320 像素地板的单框 IoU 上限是 0.35。val 的 195 个平台 FN 中至少 192 个由此必然发生。追加 stride32 也不能直接解决：本机实际分配器给该地板的正样本锚点数为 0，因此没有盲目训练这个候选。[完整实验、每类/每组错误和结构诊断](YOLO_LIFECYCLE_EXPERIMENT.md)

首次长训练进程开始后才加入训练前后指纹不变检查；该次实验的输入一致性通过独立的训练后校验确认。新检查本身已经由原生与反例回归覆盖，不能倒推声称旧进程执行了后来加入的代码。

## 独立审查与修复

1. 数据覆盖不能只相信可重哈希的元数据：重放动作后核对像素、可见框、阶段与统计，并要求每图实际选中命中的战斗帧。
2. 感知复验不能只重复记录动作：重新运行检测器、Supervisor 和策略，比较每一帧与终止状态；错误模型身份或阈值在首次检测前拒绝。
3. 运行包在预检期间可能被替换：先绑定 manifest 字节，预检后检查一致性，读取路径与最终内容再次核验；超预算轨迹在执行下一条动作之前拒绝。
4. 再运行失败任务可能产生成功包：每次只执行一次，成功清理自己创建的 staging，失败保留发生故障的那一份完整轨迹。
5. 训练文件在复制或 native 调用中变化可能造成来源误报：重新验证复制后的配置，保存调用前指纹，完成后拒绝输入变化；训练报告依据实际副本。
6. 知识导入可能超过目录大小预算而留下以后无法使用的数据库：事务内同时检查导入后逻辑大小，越界整体回滚。
7. 模型漏检不能只凭经验追加网络层：检查真实导出模型的表达上限和本机正样本分配，保留失败证据，限制模型推广范围。

最终修复、模型、方案和报告进入 [PR #3](https://github.com/www1350/maple-vision-platform/pull/3)，其最终 head 的三个作业必须全部通过后才合并。[远端逐次证据](../reports/release-0.2.0/remote-ci.json)
