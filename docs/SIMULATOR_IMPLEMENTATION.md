# 独立模拟器：已实现的离线样例

本文描述 `simulation.py` 与 `sim_types.py` 的实际行为。规则版本是 `synthetic-fixture-v1`；地图、伤害、时间、药品与资源数值都是项目自行定义的测试数据，**没有核实为国服怀旧服数值**。这个环境不连接游戏客户端、网络会话或系统输入设备。

## 接口与坐标

```python
from maple_vision.sim_types import SimAction
from maple_vision.simulation import Simulator

sim = Simulator(seed=42, job="assassin", map_id="meadow", step_ms=50)
initial = sim.snapshot()  # 渲染器和验证器专用
outcome = sim.step(SimAction("jump_attack", direction=1))
save = sim.save()  # 独立 JSON 可序列化副本
restored = Simulator.restore(save)  # 校验后创建新环境
assert restored.snapshot() == sim.snapshot()
```

`step` 返回 `StepOutcome(snapshot, accepted, reason, events)`。接受一个攻击只说明动作可以执行；是否命中由随后生成的 `attack_hit` 与状态变化验证。`accepted=True` 不是任务成功。被拒动作仍推进一个时间步，因此拒绝不能暂停冷却与世界时间。死亡后动作被拒绝为 `player_dead`，时钟继续推进。

视图为 320 × 192 像素，所有矩形使用左上角 `(x,y)` 与 `(w,h)`，`y` 向下增加。地面顶部为 `y=168`，玩家大小为 14 × 22。平台使用 `(x1,x2,y)`，从下向上可以穿过，下降时落到最先经过的平台。`sequence` 从零开始；`timestamp_ms=sequence*step_ms`；步长允许 10–100ms，默认为 50ms。同一运行中的步长固定。

世界状态、冷却、资源和随机数由模拟器持有。`snapshot()` 仅交给渲染器或独立验证；视觉策略应只接收 `ImageFrame` 生成的观测，不能收到 `Simulator` 或 `SimSnapshot`。Python 模块隔离是架构合同，不是恶意代码沙箱。

## 地图、职业与动作

两张地图 `meadow` 和 `cavern` 都有地面、高台、梯子、传送门、NPC 与三只初始怪物。初始怪物位置按种子进行小幅变化；怪物当前为静态接触伤害目标，没有巡逻、寻路或自动刷新。地图状态分别保存，往返不会重生已消灭的怪物或丢掉未拾取的物品。

| 职业样例 | 已实现的差异 |
|---|---|
| `assassin` | 远程攻击、投射物数量消耗、MP 消耗、跳跃攻击 |
| `dragon_knight` | 近身普通攻击、不耗弹药、`area` 技能最多命中三只目标 |
| `cleric` | 远程技能攻击、自我治疗、独立 MP 与生命上限 |

`CLASS_SPECS` 为只读职业规则表，策略可以读取这些静态样例能力。它不包含运行时真值。三种职业都支持移动、单段跳跃、基础 Buff、拾取和药品。没有二段跳；空中 `jump` / `jump_attack` 会被拒绝，空中普通 `attack` 仍按高度、朝向、距离及资源判断。

现有职业也可从本地 VERIFIED 合成知识目录加载完整 `ClassSpec`，以 `Simulator(..., class_spec=profile.class_spec)` 注入。实例的 `class_spec` 是只读静态规则，攻击、资源上限、消耗、冷却、移动、跳跃及治疗都使用它，不修改全局默认值。来源校验、数值范围和 CLI 见 [CLASS_PROFILES.md](CLASS_PROFILES.md)。地图及通用玩法常量不在这个职业接口内。

| 动作 | 参数与实际效果 |
|---|---|
| `idle` | 单步等待；保持空中水平惯性，地面停止移动 |
| `move` | `direction=-1/1`，每步沿水平方向移动；限制在地图范围内 |
| `jump` | 仅接地可起跳；可同时指定水平移动方向 |
| `attack` | 可指定朝向；`skill="basic"` 或龙骑样例的 `"area"` |
| `jump_attack` | 起跳与攻击一同校验；资源不足时不会只跳而不攻击 |
| `climb` | 在梯子范围内以 `direction=-1/1` 上下移动；可停留或离开 |
| `loot` | 拾取身边掉落，增加对应资源并移除掉落实体，重复拾取不重复加资源 |
| `potion_hp` / `potion_mp` | 有库存且未满时恢复资源，两类药品共享冷却 |
| `buff` | 消耗 MP，临时增加伤害；不能重复刷新仍生效的 Buff |
| `heal` | 牧师样例的自我恢复技能；满血、MP 不足或冷却中会被拒绝 |
| `interact` | 附近 NPC 的本地固定对话，可用 `target` 指定 NPC ID |
| `portal` | 地面且靠近传送门时切图，可用 `target` 指定传送门 ID |

怪物受到有效命中后减少 HP；死亡会创建一份带稳定 ID 的金币掉落。初始背包有药品，标飞样例有弹药。保存格式也支持测试场景中的 `hp_potion`、`mp_potion`、`ammo` 掉落，但默认生成器当前只掉金币。背包是这些资源的计数器，还没有装备格、重量或复杂物品属性。

NPC 对话只改变本地画面的 `dialogue` 字段；不发送玩家消息。移动、战斗或其他非等待操作会关闭对话。暂停可通过不调用 `step()` 完成；恢复不依赖墙上时间。

## 确定性与恢复

保存格式包含 schema 版本、规则集、种子、原始地图、当前地图、时间步、两张地图的实体、玩家状态、所有冷却、对话、事件与显式 64 位随机数状态。它不保存 Python 对象或执行任意反序列化代码。`save()` 使用独立容器，修改导出 JSON 不影响正在运行的环境。

默认规则继续使用 schema v1，保存字节及轨迹保持兼容；显式注入职业参数时使用 schema v2，内嵌完整职业 payload 与哈希。v2 恢复无需知识库，必须通过字段、数值、职业与哈希检查。两种版本均保持显式规则版本，不接受缺失字段的隐式回退。

`restore()` 检查版本和字段集合、有限坐标、世界边界、资源上下限、唯一实体 ID、掉落类型、布尔字段、地面与梯子位置关系、掉落 ID 计数等。无效保存返回 `ValueError`，不会改动既有实例。场景构造可以在 JSON 中指定合法初始状态；这不是对输入文件真实性的认证。文件哈希、出处和实验版本应由上层实验记录保存。

同一版本、种子、步长和动作序列产生同一轨迹；保存后恢复继续推进，也应得到相同轨迹与掉落。浮点位置在当前 Python 实现中确定性重复；这里没有声称跨任意语言、处理器与数值库的位级一致性。

## 验证范围

`tests/test_simulation.py` 覆盖动作边界、三职业差异、移动与单段跳跃、平台落地、梯子、距离/朝向/高度判断、攻击冷却和资源、范围攻击、掉落与重复拾取、药品共享冷却、治疗、Buff 到期、受伤免疫期、死亡拒绝、往返地图、NPC 对话、保存恢复和输入损坏。另有固定随机种子的 4,500 步动作序列检查坐标、资源、恢复的一致性。

这些测试验证独立样例的规则和程序合同，不证明与真实游戏完全一致，也不证明真实账号不会封禁。真实规则校验、正式素材导入、真实录像泛化和完整 24 小时墙钟长稳属于独立验收项目。
