## 本版本连续交付顺序

1. 保留 P0 测试和兼容接口；只通过显式 `knowledge init` 升级 v1 数据库，失败不能破坏旧数据。
2. 并行完成本地 catalog、asset registry、固定时步模拟器，分别验证来源、数据完整性和确定性。
3. 从自绘渲染器生成数据；检查可见框、会话划分、样本覆盖及标签污染，再执行模型训练。
4. 用像素基线先验证完整任务和独立 oracle，再接指定 ONNX；两种检测器的结果分开报告。
5. 为真实发现的缺陷增加独立回归案例，不通过降低阈值或排除失败样本制造通过。
6. 检查失败包可重复、外部进程安装 wheel 后可运行、Ubuntu/Windows CI 绑定准确提交。
7. 发布工程平台；模型质量与外部真实场景门禁独立记录。未达到准入标准的模型保留为实验产物，不能升级为默认能力。

## 接下来可独立实施的工作

| 工作 | 前置证据 | 完成标准 |
|---|---|---|
| 补足训练分布 | [视觉实现](VISION_IMPLEMENTATION.md) 中的位置覆盖报告 | 起点/边缘、空场景、清怪后、拾取后、对话及转图都进入新版本数据；保持独立会话测试 |
| 模型选择与闭环准入 | 同一版本数据和明确候选模型哈希 | 独立 test 指标、所有任务阶段识别、三职业两地图闭环；失败不能由基线结果替代 |
| 扩展知识驱动规则 | 已实现严格合成 ClassSpec 注入，需其它知识类型的已核实映射 | 逐项扩展地图、怪物、技能效果，未知或冲突拒绝加载 |
| 扩展素材渲染 | 静态 RGBA sprite 已接入；需动画、锚点与图层定义 | 支持动画帧及准确锚点，保持可见标签和几何碰撞分离，有基准图像对照 |
| 外部地图/职业包 | 版本化 Schema 和校验器 | 不改核心代码即可加载新内容；不完整包被拒绝，既有保存/回放版本可判定 |
| 真实录像与 OCR 验收 | 本地导入/OCR 工具已存在；需获准录像、语言包、独立标注 | 游戏域离线评估与错误分组，禁止合成分数代替真实成绩 |
| 24 小时长稳 | 固定提交、依赖和机器，持续运行时段 | `actual_wall_seconds >= 86400`、无未处理失败、资源趋势与中断证据；模拟时长单列 |

外部数据缺失不会阻止继续完成不依赖它的工程工作，但必须保留缺口。任何真实账号“不封号”保证都不属于模拟器可验证结论。

## 证据规则

- 一个发布提交对应准确的测试命令、环境、运行结果与 CI URL；旧提交的绿灯不自动覆盖新修改。
- fixture 实现、fixture 测试通过、模型通过、真实域通过、长稳通过是不同状态。
- 当前记录是采样 PNG/GIF 加完整动作轨迹；回放校验模拟器动作，不宣称重新执行原视觉模型。
- 基线和 ONNX 训练/测试数据哈希、阈值与模型哈希必须分别记录；参数或数据变化后重新验证。
- 计划中列出的目标比例不是已有测量值，也不能替代样本数、误差类型和未覆盖范围。
